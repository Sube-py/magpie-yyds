# magpie-yyds-usage

「只因API」（yydsapi.uno）的**用量页**：余额走势（美元）、每日消费、按模型、最近请求。

它是 [magpie-yyds](../README.md) 的配套页面包，读的是同一个账号的会话（`plugin-auth.json` 里的 `yyds`）。

## 为什么需要它

magpie 的提供商卡片里，插件账户的曲线只画**百分比**（`quota-history`），而且从插件开始上报那天才有点；站点自己的**金额**历史（累计充值 266 → 现在 43）在 magpie 里画不出来。这个页面直接读站点的账本，按金额画。

## 它怎么工作

magpie 的插件页面跑在 `connect-src 'none'` 的框架里，**不能联网**。所以：

```
page/index.html  →  带路页：把自己导航到 127.0.0.1:3491（页面唯一能做的联网动作）
lib/server.mjs   →  本地服务（只监听 127.0.0.1，检查 Host）：/ 与 /api/summary
lib/site.mjs     →  用会话读站点的 /auth/me 与 /usage（分页），算出曲线
```

**余额曲线怎么来的**：站点只给「现在余额」和逐条消费，没有余额历史接口。所以从今天的余额往回倒推：

```
balance(t) = 余额_now + t 之后所有请求的 actual_cost 之和
```

花钱的日子因此是一段向下的台阶。窗口内如果有充值，这个算式不知道（它只会加消费），页面会标注「窗口内有充值：倒推值偏高」。

## 页面内容

| 区块 | 数据 |
| --- | --- |
| 四个数字 | 余额、今日消费、区间消费、剩余比例（余额 / 累计充值） |
| 余额走势 | 金额折线（美元），从窗口起点到今天 |
| 每日消费 | 每天一根柱子，悬停看当天金额与请求数 |
| 按模型 | 区间内各模型的花费与请求数 |
| 最近请求 | 最近 20 条：时间、模型、tokens、实付 |

7 / 30 / 90 天可切。

## 安装

```sh
magpie plugin add magpie-yyds-usage     # npm 发布后
magpie plugin add /path/to/magpie-yyds/usage
```

页面在侧栏「插件 → 只因API 用量」。服务端口默认 3491，可在插件选项里改（`{"port": 3491}`）。

## 给卡片补历史（可选）

magpie 卡片上的「余额」曲线只从插件开始上报那天有点，所以一开始是平的。站点的账本里有过去，这个工具把它倒推出来写进 magpie 自己的 `quota-history.json`（会先备份）：

```sh
node tools/backfill-curve.mjs            # 45 天，每 6 小时一个点
node tools/backfill-curve.mjs --days 30 --every 3
node tools/backfill-curve.mjs --dry-run  # 只看不写
```

- 只补**比已有更早**的点，不动 magpie 之后自己记的点；
- 只写 `yyds|<账号>` 的「余额」这一条；
- 窗口内有充值时倒推会偏高，工具会提示。

## 限制

- 需要先装 `magpie-yyds` 并登录一次（本页只用它的会话，不改任何东西）；
- 只读：不签到、不改密钥、不写 magpie 的任何文件；
- 一次读 90 天约 16 页（7630 条），本机服务缓存 0 秒，刷新即重读；
- 站点偶发丢连接：单页会重试 3 次，仍失败就保留已读到的部分并标注。
